# 문제 해결 기록

프로젝트 기간 동안 만난 굵직한 문제들과 해결 과정입니다.
공통 원칙은 하나였습니다 — **추측으로 파라미터를 만지지 말고, 측정으로 원인을 소거한 뒤 원인만 고친다.**

---

## 1. 주행 성공률 30% → 100% — 범인은 주행 코드가 아니었다

**증상** 10회 순찰 중 3회만 도착. 겉보기에는 Nav2 파라미터 문제.

**진단** 용의자 다섯(배터리, 라이다, 자이로, 파라미터, 위치추정)을 수치로 하나씩 소거.

| 측정 항목 | 이전 | 이후 |
|---|---|---|
| PC-로봇 시계차 | 0.76s | 0.005s |
| 위치추정 점프 | 91회 (최대 2.77m) | 4회 (4.6cm) |
| 라이다 지연 | 0.457s | 0.001s |

**원인** PC와 로봇의 시계차 0.76초. 라이다 스캔의 타임스탬프가 과거로 밀리면서
AMCL이 "과거의 스캔"으로 현재 위치를 계산 → 위치추정이 주기적으로 깨짐.

**해결** chrony로 시간동기. **주행 파라미터 수정 0줄.**
로봇이 이상하게 움직인 게 아니라, 로봇이 어디 있는지 계산이 깨진 것이었다.

## 2. 정밀 도킹 — 지도 해상도 5cm, 요구 정밀도 mm

지도(5cm 격자)로는 충전 단자 정렬이 불가능해서, 도킹은 별도 센서 체인으로 분리했습니다.

**단계별로 기준을 하나만 사용:**

| 단계 | 기준 | 방법 |
|---|---|---|
| 접근 | 카메라 | OpenCV ArUco pose로 마커 정면까지 |
| 자세 | 라이다 | 벽 스캔점 최소자승 직선 피팅 → 절대각 정렬 |
| 깊이 | 라이다 | 자로 검증한 절대거리 기준 후진 |

**겪은 문제들:**

- **마커 크기 가정 오류** — 15cm로 가정했는데 실측 12cm. 모든 거리 계산이 1.25배 틀어져
  있었다. 이후 "가정값은 전부 실측으로 검증"이 원칙이 됨.
- **odom 기반 회전의 한계** — 제자리 180° 회전 시 슬립으로 자세가 틀어짐("삐뚤주차").
  odom 상대각을 버리고 라이다 벽피팅 절대각으로 전환해 해결.
- **IPPE pose 모호성** — 마커 법선이 두 해 사이에서 요동. 두 해의 오차 비율이 애매하면
  정면 가정으로 폴백.
- **두 기준을 한 루프에 섞으면 진동** — 벽 기준과 카메라 기준을 교대로 쓰자 조향이 흔들렸다.
  단계마다 기준 하나로 고정하니 안정.

**결과** 반복 도킹 ±2mm, 진입각 -0.23°. 끼임 감지·탈출 로직까지 실전 검증.

## 3. 라이다 사각지대 — 지도에 그린 가짜 벽은 왜 무효인가

**증상** 낮은 적재물을 라이다(단일 평면)가 못 봄. 지도 pgm에 검정으로 벽을 그려도
로봇이 그대로 통과.

**원인** obstacle layer의 raytrace clearing이 "빈 공간" 정보를 실시간으로 지워버림.
정적 지도에 그린 가짜 벽은 구조적으로 무효.

**해결** Nav2 KeepoutFilter를 별도 레이어로 구성(clearing 영향을 받지 않음) +
침범을 자동 감지하는 감시 노드(`keepout_intrusion_watch.py`)를 직접 만들어 검증.
금지구역 4개 존, 실기 침범 0건.

## 4. WiFi 대역폭 포화 — 로봇 2대를 켜자 무너진 통신

**증상** 로봇 1대씩은 정상, 2대 동시 기동 시 영상 30→10FPS, 라이다 지연 최대 7.9초,
Nav2 목표 ABORT 연발.

**원인** 무압축 고해상도 카메라 스트림이 WiFi를 포화. DDS discovery까지 밀림.

**해결**
- 영상을 JPEG chunk 기반 UDP로 전환 (1200-byte 분할, frame_seq 재조립, 미완성 프레임 0.5s 폐기)
- 해상도·fps·품질 조정 (640×480, fps/JPEG 품질 튜닝으로 약 1.3Mbit)
- FastDDS/CycloneDDS 혼용 제거, 3자 CycloneDDS 통일
- 로봇별 도메인 분리 97/88/4 — 명령·센서 혼선 원천 차단

**교훈** DDS 굶김의 원인은 대역폭 총량보다 패킷율이었다. 같은 용량이라도 잘게 쪼개 보내면
scan 9.7Hz가 유지된다.

## 5. 두 대가 동시에 출동한 1ms — 교대 시스템 경합

**증상** 충전 교대 시 두 로봇이 동시에 출발.

**진단** 로그 시각 대조 — 밀린 재시도와 신규 교대 명령이 1ms 차이로 둘 다 발사되고 있었다.
중계 릴레이 자체의 버그.

**해결** 릴레이 계층을 제거하고 서버가 직접 교대를 지시하는 단순한 구조로 변경.
중간 계층이 하나 줄자 경합 자체가 사라짐.

## 6. 안전장치 — 사고 하나당 방어 하나

실주행 사고를 겪을 때마다 방어를 구조에 심었습니다. 전부 실전에서 검증된 것들입니다.

| 방어 | 계기 | 구현 |
|---|---|---|
| E-STOP 래치 | 정지 명령이 상태 전환에 덮여 풀림 | 모든 상태 전환이 지나는 한 곳에서 래치, 관제 해제만 유효. 실전 2회 차단 |
| 스캔 감시 | 라이다 두절 상태로 벽 돌진 | scan 끊기면 즉시 정지 |
| 데드맨 | 수동조작 중 통신 두절 | 명령 0.5초 끊기면 자동 0속도 |
| 무응답 상태 | AI 판정 대기 중 서버 침묵 | "무응답"을 정식 상태로 정의, 3분기(정상/비상/무응답) 처리 |
| 조기 정지 거리 | 라이다가 로봇 앞면보다 0.19m 뒤 | 센서 기준이 아니라 차체 앞면 기준으로 정지 거리 재정의 |

## 7. 그 밖의 함정 노트

- **중복 노드는 조용히 서로를 죽인다** — 같은 노드 2개가 목표를 서로 취소해 주행 붕괴.
  기동은 반드시 CLEAN_START 스크립트로, `ros2 node list | sort | uniq -d`가 0이어야 정상.
- **param set은 재기동에 증발** — 실험으로 찾은 값은 반드시 launch/config에 박아야 남는다.
- **pkill 패턴이 자기 자신과 매칭** — 킬 스크립트가 자기를 죽이는 사고 수 회. 킬은 PID로,
  계수는 ps+awk로.
- **"안 움직인다"는 즉시 한계 신호** — 서보가 안 움직이는데 명령을 더 보내면 체류시간이
  발열을 만든다. 하드웨어는 소프트웨어처럼 재시도하면 안 된다.
